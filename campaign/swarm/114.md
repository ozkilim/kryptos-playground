# Idea 114: a chart with a flaw

**Verdict: dead in scope.**

**The idea.** The carved tableau is not perfect: row N has 31 letters where the others have 30 (the extra L).
Sanborn's K1 worksheet tableau differed from the carved one, and his key header was misspelled. If the K4 chart
had one letter too many or too few somewhere, every lookup past that point lands one cell off. Every earlier
tableau test assumes a perfect square, so it would miss an ordinary method used on a flawed chart.

**What was run** (`attacks/114_flawed_chart.py`, helpers in `kryptos/idea114_flaw.py`). The strip cell is
v = a + k (Vigenere) or k - a (Beaufort). One flaw, one cell off (d = +1 or -1) past cell t = 1..25:

* in the header (a -> a + d),
* in the row labels (k -> k + d), or
* in the strip (v -> v + d).

A fourth case models the carved chart literally: only one row is off, past one header column. Row N is row 13,
and AZ/KR and KR/KR are the carved layouts. For each flaw the 24 clue letters give a corrected key stream. Where
the flaw allows two key values at a letter, both are tried. Each stream goes through the round-11 battery
unchanged: repeating key 1-17 (skipped for row flaws, which a repeating key absorbs), sliding 1-15,
progressive 1-12, and autokey lags 1-6. A generated pre-check calls the battery only when a rule passes its
first three equations. A test checks that it never misses a battery hit. Alphabets: A-Z, KRYPTOS and 220,318
plain dictionary keyword alphabets, in five layouts, Vigenere and Beaufort. The single-row flaw ran on A-Z and
KRYPTOS only, Vigenere form, at every row.

**Numbers.**

* **K4:** 0 of 169,309,207 corrected streams pass with 7+ checks, so there was nothing to decrypt. Chance
  predicts 0.032 passes. The flaws make the search 77 times bigger than the unflawed one, which predicts 0.00056.
* **Controls:** the 3 shuffled K4s each gave 0 passes, out of 57M, 101M and 100M streams (chance predicts
  0.011, 0.022 and 0.022).
* **Planted:** 4 of 4 found, each with the flaw kind, direction and cell named:
  * a 7-letter repeating key with a header flaw at cell 12;
  * a sliding key with a row flaw;
  * a progressive key with a strip flaw;
  * a repeating key on the carved KRYPTOS chart with row N off.

  None of the four is found by the unflawed battery. The planted searches used the planted alphabet plus
  20,000 random dictionary alphabets.

**Scope limits.**

* Only one flaw of one cell. Two flaws, a moving flaw and bigger slips are not covered.
* The flaw is modelled mod 26. A real 27-letter row wraps differently, and that is not modelled.
* Not covered: stacked keys, chain addition, running keys, long non-word keys and the transposition-mixed
  alphabets.
* The single-row flaw ran on A-Z and KRYPTOS only.

**Surprising.** Not much. A flawed strip is not one-to-one, so even the right setting decrypts a few letters
wrongly: the planted strip-flaw message had 5 wrong letters out of 97. Anyone reading decrypts from a flawed
chart should expect such noise. As the old negative says, the literal carved chart's extra L sits at the end of
row N and is never reached in a normal lookup. It matters only if a reader drifts by physical column, which is
the row-13 case tested here.
