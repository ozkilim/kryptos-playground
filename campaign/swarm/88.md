# Idea 88: spaces use up key letters

**Verdict: dead in scope.** K4 gives nothing with 7 or more checks, and its near misses are what chance and the
shuffled controls give.

## The idea

Scheidt said in 2015 that special characters "don't work" and must be accounted for. If Sanborn enciphered from a
sheet that still had word spaces and the key ran on over each space, then the key position of letter i is i plus
the number of word breaks before it. Idea 56 restarted keys at words and idea 68 moved the second clue by up to 3
places, but no test let the key slip one place per word *inside* the clues.

## What was run

`attacks/88_spaces_use_key_letters.py`, helpers in `kryptos/idea88_slip.py`.

* Clue 1 written as EASTNORTHEAST, EAST|NORTHEAST or EAST|NORTH|EAST; clue 2 as BERLINCLOCK or BERLIN|CLOCK.
* The second clue gets an extra offset of 0 to 25 key places (the unknown breaks between the clues, including one
  just before BERLIN and any sentence break that eats two places). That is 3 x 2 x 26 = 156 position sets.
* For the progressive rule the number of breaks before EAST also matters; starts 0-11 cover every count for
  periods up to 12. For the other rules it does not matter.
* On each position set, `kryptos.round11.battery`: repeating key (periods 1-17), sliding key (1-15), progressive
  key (1-12), two stacked repeating keys, chain addition. Autokey is skipped, since it does not change.
* Tableaux: A-Z, KRYPTOS and 220,316 dictionary keyword alphabets, five layouts, Vigenere and Beaufort:
  2,203,178 key streams, 343,695,768 settings. Every test is exact; 7 or more checks is a hit.

The plain loop would need 344 million battery calls per ciphertext. `fast_hits` first applies cheap necessary
conditions that share work across the 156 position sets and calls the real battery only on what passes. A test
checks it returns exactly what the plain loop returns (1,074 hits compared on 40 hit-rich key streams during
development, a smaller comparison in `tests/test_idea_88.py`). Full run: 8.5 minutes.

## Numbers

| | 7+ checks | 5-6 checks (near misses) | best |
|---|---|---|---|
| K4 | 0 | 5 | 5 |
| shuffled 1 | 0 | 13 | 5 |
| shuffled 2 | 0 | 4 | 5 |
| shuffled 3 | 0 | 11 | 5 |
| chance (uniformly random key values) | 0.055 | 5.8 | |

The parsings and offsets multiply the chance rate by 98 at 7+ checks (0.00056 expected hits with the carved
positions alone, 0.055 here), a bit less than the "about 200" guessed in the plan because many offsets give the
same test for short periods. Even so the expected number of chance hits stays far below 1, so a hit on K4 would
have meant something. There was none. K4's five near misses are all sliding keys of period 14-15 or a chain
addition with 5 checks, the same kind and number as on the shuffled texts.

**Planted: 3/3.** English sentences with spaces, the clues at 21-33 and 63-73, enciphered on a random dictionary
keyword tableau with the key running over every space, spaces then removed: a repeating key (period 7), a sliding
key (period 6, Beaufort, with one double slip in the gap) and a progressive key (period 4, step 7). Each was found
with the right alphabet, layout, parsing, offset and rule, searching the whole dictionary. None of the three passes
with the carved positions, so this really was a blind spot of the earlier tests.

## Scope limits

* Exactly one slip per word break, with the five clue spellings above; a double slip inside a clue is not covered.
* 0-25 extra breaks between the clues.
* Sliding, stacked and chain tests only use letter pairs inside one word, so they have fewer checks than on unbroken
  clues (sliding: 19 differences instead of 22 when both clues are split). Long periods of those rules fall
  under 7 checks and are not tested; the repeating key always has 7 or more up to period 17.
* Plain keyword alphabets only (no transposition-mixed or hidden alphabets), Vigenere and Beaufort, no
  transposition layer, no autokey.
* 3 controls, 3 planted answers.

## Anything surprising

No. The near-miss count on K4 (5) sits on the chance prediction (5.8), and the controls spread around it (4-13;
they cluster because several related keywords give the same key stream).
