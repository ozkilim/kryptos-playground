# Idea 80: German sentence keys on keyword tableaux

**Verdict: untestable in this repository. K4 was not run. Nothing is ruled out.**

**The idea.** BERLIN CLOCK and the 1989 Berlin setting make a German sentence a natural running key. Attack 57 read
off the 13 + 11 key letters that the clues force, for every keyword alphabet, and scored them as English. A German
key would have looked like noise there. The plan was to repeat that scoring with a German quadgram model.

**Why it could not be run.** The repository has no German text at all. `data/` holds the two English quadgram
tables, the English word list, the puzzle JSONs, two key lists and the World Clock city names (single names, not
prose). A search of the whole tree for German n-gram files or German prose found nothing. No network is allowed, and
a model typed from memory would be data of unknown quality, so it was not made.

**What is needed.** Two files, letters A-Z only, umlauts written AE OE UE and sharp s written SS:

* `data/german/quadgrams.txt`: `ABCD count` per line (the format of `data/english/quadgrams.txt`), built from at
  least a few million letters of German prose.
* `data/german/sample.txt`: a few thousand letters of German prose that were not used for the table, to cut
  planted keys from.

**What was written.** `attacks/80_german_sentence_keys.py` and `kryptos/idea80_german.py`. The script looks for
the two files. Without them it prints UNTESTABLE, writes nothing to the ledger and stops. With them it runs attack
57's search unchanged (about 236k keyword alphabets, Quagmire I-IV, 4 cipher tables, 28 key letterings, 560 views per
alphabet) on K4, on 3 shuffled K4s and on 4 planted messages with German keys, using the same bar as attack 57
(K4's best must beat every control by 0.35).

**Numbers.**

| | result |
|---|---|
| K4 | not run |
| shuffled K4s | not run |
| planted German keys | none possible (no German text) |
| machinery check, stand-in language | 4/4 planted keys ranked first of 400 alphabets x 560 views |
| dry run of the full code path, English table as stand-in, smoke mode (3,000 alphabets) | planted 4/4 in the top 4 (ranks 1, 1, 1, 2); K4 -5.17 vs shuffled -5.26, -5.51, -5.28 |

The machinery check builds a quadgram table from the K1-K3 plaintexts and cuts keys from the same text. It only
shows the code is right. The dry run pointed the script at the English table through its environment variables in
throwaway mode; it repeats a slice of attack 57 and says nothing new about K4. Neither is a German result.

`tests/test_idea_80.py` (under 1 second) plants a German sentence key, with a table built from the same short German
paragraph, and checks the true alphabet and key letters come out first. One test asserts that no German model is
present; when it starts to fail, the files have arrived and the attack should be run for real.

**Scope limits.** Everything. The earlier entries that touch this (German books as known running keys, best 9/24;
attack 57 with English scoring) do not cover an unknown German key on a keyword tableau.

**Worth knowing before running it.** Attack 57 showed the limit of this method for English: 24 key letters give
only 18 quadgrams, the noise ceiling over 92.5M settings was about -4.88, and planted keys scored -4.30 to -4.83. A
German run will have the same thin margin, so a clean negative will again be "partial", not "solid".
