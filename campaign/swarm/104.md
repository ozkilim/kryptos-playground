# Idea 104: close the two holes the audit found in the key-rule battery

**Verdict: dead-in-scope.** K4 gives 0 passes in 43.7 billion exact tests; so do three shuffled K4s.

## The idea

Idea 91 fed 678 textbook-enciphered messages to the round 9-11 tests. Attack 66 missed 115 that had enough checks,
for two reasons. Neither was evidence about K4; they meant K4 had never been tested there.

* **(a) Two stacked key words.** The key is two repeating words of lengths p and q added together. The old code added
  two partial counts and dropped the pair when the sum was under 8, before its exact solve ran. That dropped 20 of the
  41 pairs p < q <= 13 that really have 7 or more checks. `kryptos.round11.battery` has the same filter, so attacks 68,
  70, 71B, 78, 81 and 88 dropped pairs too.
* **(b) The number of the fed letter.** Autokey was tested only with the fed letter numbered on the keyword alphabet M.
  The usual Quagmire I autokey (key letter found on the straight cipher strip), its mirror, and rows picked by the A-Z
  labels carved on Kryptos number it on A-Z or KRYPTOS instead. The same goes for a progressive key moved on in A-Z order.

## What was run

`attacks/104_stacked_pairs_and_feed_numbering.py`, helpers in `kryptos/idea104_holes.py`. 666,993 keyword alphabets
(dictionary keyword alphabets, both transposition-mixed forms, A-Z, KRYPTOS), five layouts, Vigenere and Beaufort form,
65,510 exact tests per alphabet, 7 or more checks required. K4 took 328 s; the whole run 14 minutes.

The stacked test has no pre-filter. Each key letter is a node, each clue letter an edge joining the two key letters
added there; the key fits exactly when the key values add to zero, with alternating signs, around every loop. The number
of independent loops is the true number of checks. This equals attack 66's mod-13 / mod-2 solve (tested on all 54 pairs)
and is also exact mod 27-31, where the old battery only had a necessary test.

True checks of the 20 dropped pairs: (3,11) 11, (3,13) 10, (4,11) 10, (4,13) 8, (5,9) 11, (5,11) 9, (5,12) 8, (5,13) 7,
(6,9) 12, (6,10) 10, (6,11) 8, (6,13) 7, (7,8) 10, (7,9) 9, (7,10) 8, (7,11) 7, (8,9) 8, (8,10) 11, (8,12) 8, (9,12) 7.

## Scope limits

* Keyword tableaux from the repository's vocabulary only. Two stacked words only.
* 13 pairs p < q <= 13 have fewer than 7 checks and stay undecidable: (7,12) (7,13) (8,11) (8,13) (9,10) (9,11) (9,13)
  (10,11) (10,12) (10,13) (11,12) (11,13) (12,13).
* The variants were run only at the pairs the old filter dropped inside each variant's own scope, one variant at a time.
  The 41 longer pairs were run on the plain clue letters only.
* Autokey: one fixed lag 1-6; not the keyed-lag form of attack 74; not combined with the variants.
* Attack 89 (non-keyword alphabets) uses the same battery and was not rerun.
* No survivor appeared, so the reading stage only ever ran on planted messages. A survivor under "word breaks", or at a
  pair whose graph falls into pieces, could have been read only in part.

## Surprises

* The old filter dropped far more inside the variants than on the plain clues: 622 (position set, pair) tests with one
  letter left out and 4,852 with word breaks, some with up to 18 exact checks, because a missing letter or a break
  cuts the runs the filter counts over.
* 41 more length pairs with a long second word (14-45 letters) have 7 or more checks and were never on any list, for
  example (2,15) 8, (3,20) 9, (8,20) 11. When the second word has 14, 21 or 42 letters the second clue meets the same
  key letters as the first (the clues are 42 apart), so the checks are real but only 26 letters could be read.
* The loop test is exact for every modulus, so the "necessary test" the round 11 battery used mod 27-31 can be replaced.
